Root cause proven by Linux 6.6 fs/squashfs/id.c:
  no_ids=1 requires an 8-byte ID index table.
  v42.21 encoded bytes_used-id_table_start=10 because the 2-byte OEM checksum
  was incorrectly added to the SquashFS superblock length.
  v42.22 restores bytes_used-id_table_start=8 and keeps the OEM checksum at
  the same 4 KiB-aligned external trailer location.

Expected boot change:
  no "unable to read id index table"
  VFS: Mounted root (squashfs filesystem) readonly
  Run /sbin/init as init process
