# Tenda Nova MW5 v43.10 - RTL8197F OEM CDP completion

v43.10 is based directly on the hardware-tested v43.9 tree.

## Hardware facts carried forward

- RTL8197FS CPU DMA uses six DWORD / 24-byte New_swNic descriptors on MW5.
- RTL8367 switch-to-CPU frames can arrive with EtherType `0x8899` and the
  observed RX word `0x0401` for physical switch port 1 (DSA `lan`).
- CPU-to-switch DSA TX uses the protocol-9 destination-mask form (`0x9202` for
  LAN port 1 and `0x9208` for WAN port 3).
- v43.9 proved that the RX `0x0401` decoder works and that CPUTPDCR0 advances
  for real TX DMA completions.

## v43.10 correction

The RTL8197F OEM `New_swNic` implementation uses the hardware current
 descriptor pointer (CDP) as the authoritative completion cursor for the
24-byte rings.

RX (`USE_SWITCH_RX_CDP` semantics):

- software index != CPURPDCR0 index: consume the descriptor even when OWN still
  appears set;
- software index == CPURPDCR0 index and OWN clear: consume the RX-runout packet;
- software index == CPURPDCR0 index and OWN set: no packet is available;
- invalid/out-of-ring CPURPDCR0: fall back to OWN.

TX (`USE_SWITCH_TX_CDP` semantics):

- reclaim every queued descriptor before the CPUTPDCR0 index;
- do not block reclamation on a stale OWN bit;
- explicitly restore reclaimed descriptors to CPU-owned state before ring wrap;
- invalid/out-of-ring CPUTPDCR0 falls back to OWN cleanup.

The existing v43.9 switch-to-CPU tag decoder is retained unchanged in
semantics. Standard OpenWrt firewall4 configuration is also retained.

## Added runtime counters

`/proc/rd05-rtknet` now reports RX CDP-complete/runout/empty/fallback counters
and TX CDP-clean/stale-OWN/invalid/fallback counters. The first malformed RX
completions also dump descriptor words and the first bytes of the associated
RX buffer, bounded to avoid unbounded printk traffic.

## Test

After a successful build and flash, wait for normal OpenWrt boot and run:

```
mw5-netdiag
```

No additional router commands are required for the built-in LAN/WAN sequence.
