# Tenda Nova MW5 v43.5 wired-path correction

## Evidence from the separate physical-port tests

The two serial captures identify the ports consistently:

- Physical LAN socket: RTL8367 port 1, Linux DSA device `lan`.
- Physical WAN socket: RTL8367 port 3, Linux DSA device `wan`.
- RTL8367 CPU link: port 6 to RTL8197F P0/RGMII.

Both user ports reached link-up and received traffic. In each test the active
DSA device accumulated RX packets but remained at zero TX packets. The direct
LAN test also bypassed `br-lan` without changing that result. Therefore v43.5
does not swap the DTS port labels and does not replace the verified topology.

## Source changes

### Factory-MAC and RTL865x tables

The preinit driver opened `eth0` with a temporary random address and seeded the
RTL865x VLAN/L2/netif/ACL tables with that address. OpenWrt installed the OEM
address later. v43.5 replaces the generic `ndo_set_mac_address` hook with a
wrapper which records every MAC change and re-runs the external-switch table
seed while the interface is active. When the address is set while the interface
is down, the normal next `ndo_open` seeds the tables with the already updated
address.

The currently programmed address and the last address used for the tables are
visible in `/proc/rd05-rtknet`.

### Protocol-9 DSA receive validation

The Linux EtherType tag removal sequence remains compatible with the Linux 6.6
DSA helpers. v43.5 additionally reads the encapsulated EtherType before the tag
is removed, keeps it explicit until the DSA receive core selects the user port,
and emits bounded diagnostics for the first TX/RX frames and malformed tags.
This distinguishes ARP (`0x0806`), IPv4 (`0x0800`) and other traffic without
flooding the serial console.

### Raw RTL8197F receive tracing

The existing pre-DSA raw-frame trace is enabled for both supported external
switch boards, including the MW5. `/proc/rd05-rtknet` exposes its counters,
last descriptor words, ring registers, MAC state and TX state.

### Built-in router tests

`mw5-netdiag` now supports:

```sh
mw5-netdiag direct lan
mw5-netdiag direct wan
mw5-netdiag direct auto
```

`auto` chooses the DSA port whose carrier is active. All test commands remain
inside the OpenWrt tree and are installed in the image. The compatibility name
`MW5_V43.3_DIRECT_LAN_DIAG_FIX.sh` delegates to the maintained tool.

## Test after flashing

For either socket:

```sh
mw5-netdiag state before
mw5-netdiag direct auto
```

Generate ARP and ping traffic from the attached PC, then run:

```sh
mw5-netdiag state after-direct
cat /proc/rd05-rtknet
dmesg | grep -E 'MAC sync v43.5|rtl4_9 v43.5|rd05 rxtrace'
```

Restore the normal router topology with:

```sh
mw5-netdiag restore
```

## Validation boundary

The source-level correction and static regression checks are complete. A full
MIPS OpenWrt cross-build and the final ARP/DHCP/ping result require the user's
OpenWrt build environment and physical MW5. v43.5 intentionally adds enough
bounded diagnostics to identify any remaining hardware-specific mismatch from
one post-flash log.
