# Tenda Nova MW5 v43.8 RX descriptor / DSA integration

This tree targets RTL8197F/RTL8197FS with the external RTL8367-family switch.
The confirmed physical mapping remains LAN=P1, WAN=P3, CPU=P6.

## RX policy

At the Linux DSA master boundary, DSA must see:

    DA | SA | 0x8899 | protocol-9/source-port | original EtherType | payload

v43.8 supports two hardware outcomes:

1. If P0 leaves the switch CPU tag in the DMA buffer, it is passed unchanged.
2. If RTL8197FS consumes the CPU tag but exposes source port in opts4[15:13],
   the master inserts an equivalent four-byte tag before `eth_type_trans()`.

The fallback is intentionally limited to source port 1 and 3 because those are
the two values proven by MW5 hardware captures.

## DMA/ring lifetime

The old delayed-linkup reseed could write active current-pointer registers back
to the ring base after traffic had started. v43.8 disables that delayed reseed
on MW5 and makes ordinary reseed/MAC-change operations table-only. Ring base and
geometry programming remains confined to hardware start/reset and explicit
`rxstart` diagnostics.

## Firewall

The standard OpenWrt firewall is restored. Clean installs use the package
firewall defaults. Upgrades from v43.7 migrate from
`/etc/config/firewall.mw5-disabled-backup` or `/rom/etc/config/firewall` and
re-enable firewall4.

## Hardware test

After flashing, use the serial console and run only:

    mw5-netdiag

Start with the cable in LAN and move it to WAN when prompted. Relevant v43.8
markers include:

    mw5 rxdesc-dsa v43.8: synth ...
    rtl4_9 v43.8 RX ...
    rtl4_9 v43.8 TX ...
    mw5 tx-wire v43.8: pre-dma ...

Also inspect `/proc/rd05-rtknet`; `mw5_rx_dsa` shows whether hardware preserved
the tag or the descriptor fallback reconstructed it.
