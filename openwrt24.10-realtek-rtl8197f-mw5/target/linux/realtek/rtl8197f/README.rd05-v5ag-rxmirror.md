# RD05 v5ag RX mirror probe

Base: v5af/v5ab line.  This keeps the stable VID9/PVID/SWCORE setup and adds a
single RTL8367D diagnostic mirror step.

v5af proved that the RTL8197F RX DMA path sees 0x8899-tagged packets generated by
the router itself, but PC ARP still does not appear as raw ARP at offsets 0/4/8
while lan2 broadcast counters grow and dot1dTpPortInDiscards stays zero.

v5ag therefore configures the RTL8367D mirror block:

* RX source mask: all DSA user ports
* monitor port: the DSA CPU/EXT1 port
* RX VLAN/isolation leaky for mirror copies

Expected boot marker:

    RTL8367D RD05 RX mirror v5ag: cpu=0x80 cpuport=7 users=0x1f rxmask=0x1f mirror src/ctrl/ctrl2=...

Test with:

    rd05-netdiag arptest 45

If rd05_rxtrace_arp8 or rd05_rx_arp starts increasing, the normal RTL8367D
flood/L2 path is the blocker and mirror copy confirms the host path can carry PC
ARP.  If ARP is still absent, the frame is not being delivered to the CPU RGMII
path even by mirror, and the next focus is external switch CPU-port/trap routing
or the upstream rtknet/RGMII path.
