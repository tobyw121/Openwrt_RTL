# Tenda Nova MW5 v43.12 - RTL8367 4-byte TX tag correction

## Scope

v43.12 is intentionally a narrow follow-up to v43.11. The v43.11 hardware run
showed that RX descriptor handling, FCS accounting, KSEG1 descriptor access and
TX completion are now stable. The remaining failure is egress from the
RTL8197F P0 CPU-facing link through the RTL8367 to the selected user port.

## Hardware evidence from v43.11

The router receives the PC's ARP frame with the real switch-to-CPU tag
`0x8899 0x0401`, routes it to DSA LAN port 1 and builds an ARP reply for the
correct client MAC. The master driver then submits and completes the TX DMA
entry. Across the completed run there are no RX descriptor errors, no RX drops,
no TX ring-full events and no TX timeouts.

The v43.11 tagger nevertheless emitted `0x9202` for LAN and `0x9208` for WAN.
The extra `0x0200` bit was inherited from an earlier SDK interpretation as a
"disable learning" bit. The four-byte Realtek tag format used by the Linux
rtl4a reference instead constructs the CPU-to-switch word from the protocol
nibble and destination port mask only.

## v43.12 change

CPU -> RTL8367 four-byte tag:

- LAN / physical port 1: `0x8899 0x9002`
- WAN / physical port 3: `0x8899 0x9008`

The tag word is:

```
(protocol 0x9 << 12) | destination_port_mask
```

No speculative bit 9 is added.

RX is deliberately unchanged:

- observed switch -> CPU LAN tag: `0x8899 0x0401`
- the `s2c-0400` decoder remains active
- the descriptor fallback remains only a compatibility fallback

## Unchanged v43.11 data path

The following are retained byte-for-byte in functional logic:

- six DWORD / 24-byte descriptors
- KSEG1 uncached descriptor access
- OEM FCS/CRC length convention
- RX CDP completion policy
- TX CDP completion policy
- single TX ring 0 (`TXRINGCR=0x1`)
- P0/RGMII TX delay 0, RX delay 5
- LAN port 1, WAN port 3, CPU port 6
- standard OpenWrt firewall

The Ethernet master driver therefore retains its v43.11 version string. The
revision change is in the DSA tagger and built-in diagnostics.

## Test

After build, flash and normal boot, run only:

```
mw5-netdiag
```

Expected diagnostic markers include:

```
tx-tag-expected=LAN:0x9002 WAN:0x9008 RX-LAN:0x0401
rtl4_9 v43.12 TX ... tag=0x9002 ...
rtl4_9 v43.12 RX layout=s2c-0400 ... tag=0x0401 ...
```

The decisive success condition is that LAN/WAN switch-port TX counters begin
to increase and ARP/ping succeeds while master `submit` and `complete` remain
1:1.
