# Patchfix 1: malformed Realtek kernel patches 720 and 723

This fix applies to the OpenWrt 24.10 Realtek Linux 6.6.114 driver-port tree.

## Root cause

Two custom SoC-selection lines were added to upstream-derived patches without
updating the unified-diff hunk counts:

- `720-add-rtl-phy.patch`: the first hunk declared 12 new lines but contains 13.
- `723-net-mdio-Add-Realtek-Otto-auxiliary-controller.patch`: the first hunk
  declared 16 new lines but contains 17.

GNU `patch` therefore stopped at the final context line and reported a
`malformed patch`. The diffstat metadata was updated as well.

Five older custom patches were also normalized so the complete active series is
accepted by strict unified-diff parsers:

- `301-mips-add-rtl8197f-platform-kconfig.patch`
- `303-mips-realtek-rtl8197f-force-little-endian.patch`
- `309-net-ethernet-add-rtl8197f-ethdiag.patch`
- `324-net-ethernet-add-rd05-oem-switch-preinit.patch`
- `326-rtl8197f-rtl8367d-mainstream-offload-notes.patch`

These five changes only correct hunk counts or a missing context-line prefix;
they do not change kernel source code generated by the patches.

## Validation

- All 37 active patches pass `git apply --numstat` without `--recount`.
- All 37 active patches pass GNU `patch` syntax parsing.
- Patches 720 and 723 apply with `--fuzz=0` to the relevant Linux 6.6.114 file
  state after the OpenWrt generic PHY/MDIO transformations.
- The port validator now performs both strict parser checks, preventing this
  class of error from passing validation again.
- Current validation result: `PASS=134 WARN=4 FAIL=0`.

This is a patch-format and targeted-application validation. It is not a claim
that a complete firmware compile or hardware test has passed.

## Rebuild after updating an existing tree

The failed preparation left a partially patched kernel directory. Remove it via
OpenWrt's target clean rule before retrying:

```sh
cd /path/to/openwrt-root
make target/linux/clean
make -j1 target/linux/compile V=s
```
