User UART log from22.11.2026 confirms commit a8b5cef9b6 is running.
Before load:441 RX packets, zero drops. After load:4768 RX packets,
3960 drops; bad_tag3912, bad_port1, bad_l3=47. TX completes4317 packets;
CDP invalid/defer/OWN disagreement remain zero. No RX metadata instability,
address mismatch, DMA error or runout is reported. A rejected1474-byte frame
starts99bfea7acfad086a7c542d6a11107ed004be460c00365c2c; descriptor DW1
matches82939000. Thus the preceding TX/alias/snapshot changes did NOT cure
RX data corruption. No additional timing/FIFO/DMA changes are made on this
inconclusive evidence. In particular this is not proof of a complete switch
crash: RX/TX continue, while corrupted frames are dropped by the guard.

## WLAN fixes (package release8)

The log shows manual module probe, one wlan0 interface of type managed with
zero MAC, no AP, early efuse-in-suspend and empty RF parameter path. There is
no integrated2.4GHz device. The existing package still only drives PCI5GHz;
no full8197G integrated driver is implemented by these fixes.

Patch107 supplies a R76-only RF root in the Linux PHL type header as well as
the later platform header. Without OEM NVM, rtw_nvm_fill_full_para_path is an
empty macro; the adapter parameter path is now assembled explicitly from
rtw_phy_file_path plus rtl8832bre/RFE50/. The HAL also has its own path-building
logic: an empty adapter log alone did not prove that every HAL file read was
empty, so no claim is made that this is the only WLAN fault.

Registration checks for invalid adapter MAC and generates a temporary locally
administered address when needed, logging the fallback. Valid factory/user
addresses are preserved. This avoids publishing a null BSSID, but does not
repair efuse/power sequencing or replace per-device calibration. No flash
access, OEM NVM writes, hardcoded factory MAC or automatic radio enabling.
Loading the module creates a managed interface; AP visibility additionally
requires valid hostapd/netifd configuration and a successful hardware start.

## Validation

Production registration and NVM-less path functions compiled/executed with
UBSan mocks. Tests preserve valid MACs and verify /etc/conf/rtl8832bre/RFE50/.
PHL header preprocessed independently before the platform header. Probe frame
builder verifies Ethernet length, EtherType and marker layout. Related prior
port/regression tests pass. Patch107 applies with fuzz0 after100..106.
No MIPS firmware build or hardware validation here. MW5 files unchanged.

## Isolate RX corruption using marked, non-routed Ethernet probes

This test can also be run on the current1.8.50 firmware; no new flash needed
for Ethernet diagnosis. First keep WLAN unloaded and WAN disconnected to
isolate the direct PC-to-router path. Do not change switch registers.

Router UART38400, before test:

```
cat /proc/cudy-r76-rtknet > /tmp/r76-probe-before.txt
ethtool -S wan > /tmp/r76-probe-wan-before.txt
tcpdump -ni eth0 -s 0 -w /tmp/r76-probe-router.pcap 'ether proto 0x88b5 or (ether[12:2] = 0x8899 and ether[20:2] = 0x88b5)'
```

Leave tcpdump running. PC, another terminal:

```
cd ~/Schreibtisch/openwrt_git_RTL/Openwrt_RTL
sudo ip link set dev enx00e04c5562c0 up
sudo ip addr replace 192.168.1.3/24 dev enx00e04c5562c0
ping -I 192.168.1.3 -c 3 192.168.1.1
sudo python3 scripts/diagnostics/r76-rx-probe.py --iface enx00e04c5562c0 --seconds 60 --output /tmp/r76-probe-sent.pcap
```

The output PCAP must not already exist. The script resolves the current
router LAN MAC from the existing neighbour entry. It sends controlled frames
of60,64,74,75,98,128,256,512,1024,1400,1474,1514 bytes without FCS, with
EtherType88b5, R76P markers and offset/sequence fields. It does not change
routes, network manager or router configuration; these packets are not routed.
A valid router ARP neighbour must already exist (ping primes it).

After the script finishes, Ctrl-C tcpdump on router. Then router:

```
cat /proc/cudy-r76-rtknet > /tmp/r76-probe-after.txt
ethtool -S wan > /tmp/r76-probe-wan-after.txt
tar -czf /tmp/r76-rx-followup.tar.gz -C /tmp r76-probe-before.txt r76-probe-after.txt r76-probe-wan-before.txt r76-probe-wan-after.txt r76-probe-router.pcap
```

PC:

```
scp -O root@192.168.1.1:/tmp/r76-rx-followup.tar.gz .
cp /tmp/r76-probe-sent.pcap .
```

Upload both. Driver-rejected frames cannot appear in tcpdump; compare missing
sizes/sequences with before/after bad_tag counters. If isolated RX works,
repeat in a fresh output path with WAN workload to establish load dependence.

## Separate5GHz test after installing release8

Router UART, individually:

```
modprobe rtk_wifi6
cat /sys/module/rtk_wifi6/parameters/rtw_phy_file_path
iw dev
wifi config
uci -q get wireless.radio0.disabled
logread | tail -80
```

Use LuCI to configure/enable the existing5GHz AP and then collect iw dev and
logs again. wifi config detects devices, but does not promise a running AP.
Do not share wifi status unfiltered because it includes keys.2.4GHz remains
unavailable until its separate integrated driver is ported.
