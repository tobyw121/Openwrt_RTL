# RD05 OEM idle/ping comparison, 2026-10-31

Both archives identify collector 1.2. They contain two complete snapshots each:
- idle: 431..561 and 562..692 seconds uptime, requested 60, observed 262 seconds.
- ping: 787..919 and 920..1051 seconds uptime, requested 60, observed 265 seconds.
Each snapshot took 130..132 seconds. Thus this is not a five-second-resolution
trace. Before/after fields within a snapshot are sequential, not simultaneous.
No timed-out/limit query status was recorded; each archive has 176 error entries,
mainly unsupported ethtool operations and unavailable/down interface attributes.
Unknown vendor callbacks were inventory-only in version 1.2.

Internal ASIC P0 deltas between snapshots:
- idle: RX +75476 bytes, TX +34704 bytes, CRCAlignErr/SymbolErr zero.
- ping: RX +95579 bytes, TX +71994 bytes, CRCAlignErr/SymbolErr zero.
TX ring position 146->315 idle; 757->394 (wrap at 768) ping.
RX ring position 1366->1800 idle; 565->1177 ping.
These are successful OEM internal dataplane observations, not proof that external
DSA-port mappings or Linux descriptors should copy every OEM selector.

Ping PCAP: 125 frames, 58 ICMP requests and 58 replies, two ARP requests/replies
and five IPv6 frames. Tcpdump reports zero dropped packets. The capture overlaps
only the first minute of the longer collection.

PCI: one enumerated device 10ec:f812, class 028000, OEM IRQ 5. This IRQ is a Linux
mapping and must not be copied into the OpenWrt device tree.
GPIO: registered controller rtl819x_gpio; registration is not a complete pin map.
External switch readback confirms 1307=5,13f9=124,121a=2b9,1303=7d6,1304=7544,
1d70=2000,12c7=76,12cf=ffff,00ee=4800. No new switch timing difference identified.
MMIO read requests produced format-error messages; do not treat those commands'
zero exit status as successful MMIO readback or infer current register values.

No new hardware fix is established. Prioritize the paired OpenWrt TX diagnostic
already implemented in 9cb965a969 over another broad OEM read attempt.

## Additional OEM evidence

The earlier OEM LAN PCAP oWNedj contained 25 requests/25 replies; aLVgqO
contained 30 requests/24 replies and PC address transition ARP. ICMP Ethernet
frames were 98 bytes without captured FCS. Router ARP replies were 60 bytes,
including 18 zero padding bytes. IPv4/ICMP checksums were valid.

The manual packet-buffer archive did contain eight 128-byte reads. However,
all selected descriptors 0..7 were CPU-owned while the current TX position was
545. Repeated pointers and reused contents prevent a valid descriptor/payload
pairing. These dumps do not establish OEM corruption. Do not repeat arbitrary
reads of old pointers.

The driver collector run recorded 66 seconds and eight snapshots, but skipped
module extraction because MemAvailable at extraction time was below 32 MiB.
This is not contradicted by an earlier meminfo snapshot reporting 37564 KiB.

The subsequently streamed /lib/modules archive contains 70 .ko files. No
rtl8192cd, Realtek Ethernet or external-switch .ko is present. Together with
symbols already decoded from the OEM kernel this supports built-in driver
implementation, not absence of the hardware or driver. Presence in this archive
alone does not establish whether a module was loaded.

Notable ancillary modules: xt_flowMARK (QoS tags), ip_account (IP accounting),
wandt_filter and enid (Netfilter hooks), passthrough (packet processing). Their
full semantics are not reconstructed. The module ELF headers identify ELF32,
little endian, MIPS32r2/o32; inspected vermagic is Linux 4.4.176. Files were never
loaded/executed. MTD test .ko files are filesystem modules, not MTD partition
contents; they were not run.

The collector 1.1 panic address 803fae9c maps in our archived OEM kernel to
rtl8192cd_proc_get_user_ie_info. A per-file trace from the crash is unavailable,
so exact faulting path/cause is not proven. Collector 1.2 disables unverified
vendor reads; 1.3 adds explicit regular module-file extraction.

No finding above proves a new LAN/WAN fix. Implemented RD05 register corrections,
RGMII sequencing and bounded TX publication diagnostics remain hardware-unproven
as a complete solution. Software snapshots cannot establish actual DMA fetch
bytes or wire FCS. MW5 must remain outside RD05-specific changes.

Raw archives and full local extraction directories are retained outside the
repository. This document and module-inventory.json preserve the reusable facts;
they are not a claim that all OEM code has been reverse-engineered.
